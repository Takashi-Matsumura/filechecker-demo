# セキュリティレビュー（アプリ全体） 2026-11-07

対象: main `928bb20` 時点のアプリ全体（差分ではなく全体の見直し）。所見はすべて修正済み（#47。追補の対応は #48）。
前提: このアプリは社員の PC 上で動き、localhost からのみ使う（proxy.ts で Host / Origin を制限）。
想定した攻撃者:
1. ブラウザで開いた悪意ある Web ページ（CSRF・DNS リバインディング）
2. 棚卸し対象のフォルダにファイルを置ける人（細工したファイル・リンクの差し替え）
3. ファイルの中身による AI への指示の注入

## 確認して問題なしとしたもの

- **proxy.ts**
  - Host ヘッダが localhost 系以外のリクエストは拒否している。DNS リバインディングや、LAN・トンネル経由のアクセスを防げる。
  - 状態を変えるリクエストには Origin を必須にしている。`null` や `localhost@evil.com` のような形も拒否される。
  - matcher を指定していないので、すべてのルートに効く。
  - GET の応答には CORS ヘッダがないので、他のオリジンからは読めない。
- **スキャンのルート（resolveScanRoot）**: realpath で解決してから、許可ルートの配下にあるかを確かめている。再開するときにも確かめ直す。
- **ファイルの読み出し（safeFilePath / openValidated / stillSameFile）**
  - lstat で、最後の要素がリンクのものを拒否する。
  - realpath で、スキャンのルートと許可ルートの配下にあるかを確かめ直す。
  - O_NOFOLLOW で開いたあと、dev と inode で同じファイルかを確かめる。
- **走査（walk）**: シンボリックリンクは辿らない。隠しフォルダと node_modules は飛ばす。
- **ファイラーで表示（reveal）**
  - パスはクライアントから受け取らず、ID から DB の記録を引いて検証したものを使う。
  - execFile で起動するので、シェルを介さない。
  - mac では `--` で引数を区切っている。Windows では、`"` を含められないパスを引用符で囲んでいる。
- **API の入力検証**
  - ID は整数かを確かめている。
  - status は許可された 3 つの値だけを受け付ける。
  - filter は許可リストで照合し、q は 200 文字に切る。page は 0 以上の整数にそろえる。
  - version は 8 桁の 16 進数か、scan は正の整数かを確かめる。
- **SQL**: すべてプレースホルダを使っている。値を埋め込んでいるのは定数の列リスト（`LIST_COLUMNS`）だけ。
- **画面（XSS）**: `dangerouslySetInnerHTML` や `innerHTML` は使っていない。リンク先は数値の ID だけで組み立てている。
- **LLM の接続先**: 環境変数 `LLM_BASE_URL` だけで決まり、ユーザの入力からは決まらない（SSRF なし）。AI には、ルールで番号を伏せた本文を渡している。
- **Office の ZIP 爆弾**
  - 必要な XML だけを展開する。
  - 展開後のサイズの合計と件数に上限があり、圧縮形式も確かめている（ただし、展開後の XML の処理時間は所見 2 を参照）。
- **画像のピクセル爆弾・PDF の描画サイズ**: デコードや描画の前に画素数の上限を確かめている。
- **保存するデータ**: 抜粋・要約・OCR のプレビューは伏せたあとのもの。氏名そのものは保存せず、位置だけを残す（例外は所見 7）。性能分析の表は数字だけ。
- **CI**: 権限は読み取りだけ。外部の入力（PR のタイトルなど）を run に埋め込んでいない。`persist-credentials: false` を指定している。

## 追補（見ていない範囲の続き、#48）

- **`npm audit`**: 中程度の脆弱性が 8 件あるが、すべて開発用の依存だった。ESLint 経由の `minimatch`（GHSA-g3hv-75wg-m249）で、信頼できない glob パターンを渡したときの DoS にあたり、このアプリには当てはまらない。本番の依存（`npm audit --omit=dev`）は 0 件。版を上げると Lint が壊れるおそれがあるため、対応は見送った。
- **PDF の文字抽出の上限**: これまでは全ページを同時に読んでいた。読むのは先頭 500 ページ・20 万文字・60 秒までとし、打ち切ったときは補足に表示するようにした。あわせて、埋め込み画像の展開サイズに上限（`maxImageSize`）を設け、読み終えたら資源を解放する。テストは tests/extract.test.ts。
  - 1 ページの解析の途中では止められない（PDF.js は Node ではこのプロセスの中で動くため）。上限はページとページの間で確かめている。
- **未確認のまま残っている範囲**: PDF.js と @napi-rs/canvas の内部の脆弱性、画面のコンポーネントの 1 行ずつの精読、Windows / Linux での実機の動作。
